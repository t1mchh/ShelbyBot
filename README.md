# Shelby Family Bot — Nova RP

Готовый Discord-бот для действующего состава семьи Shelby: приветствие и стартовая роль, сборы с сохраняемыми ответами, временные голосовые комнаты, отчёты на премию и очистка сообщений. Бот не включает систему заявок или рекрутинга.

## Требования

- Python 3.11+
- Discord-бот, созданный в Discord Developer Portal
- SQLite-файл на постоянном диске хостинга

## Установка и настройка

1. Загрузите папку `ShelbyBot` на сервер или в файловый менеджер Bot-Hosting.net.
2. Выполните `pip install -r requirements.txt`.
3. В начале `main.py` замените нули у `GUILD_ID`, `STARTER_ROLE_ID`, `WELCOME_CHANNEL_ID`, `SBOR_CHANNEL_ID`, `STAFF_ROLE_ID`, `REPORTS_CHANNEL_ID`, `VOICE_TRIGGER_CHANNEL_ID`, `TEMP_VOICE_CATEGORY_ID` и `MOD_LOG_CHANNEL_ID` на ID соответствующих объектов. Неиспользуемый ID оставьте равным `0`.
4. В панели Bot-Hosting.net добавьте переменную окружения `DISCORD_TOKEN` со значением токена. Токен в файлы проекта не помещайте.
5. Установите запуск `python main.py`.
6. Запустите бота. База автоматически создаётся в `data/shelby.sqlite3`; убедитесь, что каталог `data` сохраняется между перезапусками и деплоями.

ID включают через Discord: включите режим разработчика в **Настройки пользователя → Расширенные**, затем правой кнопкой нажмите на сервер, канал, категорию или роль и выберите **Копировать ID**.

## Discord Developer Portal

В **Bot → Privileged Gateway Intents** включите:

- **SERVER MEMBERS INTENT** — для приветствий и списка участников выбранной роли при рассылке.
- **MESSAGE CONTENT INTENT** — запрошен в настройках кода, хотя бот не читает содержание сообщений.

`Voice States` не является privileged intent: в коде включён `voice_states`. В приглашении бота и настройках ролей выдайте ему `View Channels`, `Send Messages`, `Embed Links`, `Read Message History`, `Manage Messages`, `Manage Roles` (и поставьте роль бота выше стартовой роли), `Manage Channels`, `Move Members`, `Connect`, а также доступ к нужным категориям и каналам. Для голосовых комнат проверьте наследование разрешений категории.

Добавьте бота через OAuth2 URL Generator со scope `bot` и `applications.commands`. Не выдавайте `Administrator`, если достаточно отдельных прав.

## Команды и поведение

- `/sbor роль событие время duplicate_dm` — доступ старшему составу или администраторам; публикация сборов в `SBOR_CHANNEL_ID`, кнопки ответа сохраняются в SQLite. При рассылке бот отправляет личные сообщения участникам выбранной роли с паузой.
- `/setup_reports` — доступ администраторам; создаёт панель в текущем канале. Отчёты уходят в закрытый `REPORTS_CHANNEL_ID`; старший состав может отметить выплату.
- `/clear amount` — пользователи с `Manage Messages`, диапазон 1–100. Старые сообщения, которые Discord не позволяет удалить массово, могут остаться; результат показывается вызывающему пользователю.
- Автомодерация проверяет сообщения и их правки, удаляет запрещённые оскорбления, предупреждает автора и пишет закрытый журнал. Проверка учитывает регистр, похожие латинские/кириллические символы, разделители, zero-width символы и растягивание букв. Слово о птице разрешено при явном контексте птицы или фермы; высказывания про хиджаб удаляются только при обнаруженном оскорбительном контексте. Слова «белый», «натурал» и «гетеросексуал» проверяются только в серверном никнейме как теге, не в обычных сообщениях. Боту нужны `Manage Messages` и право писать в канал журнала.
- При входе участника бот выдаёт стартовую роль и отправляет приветствие.
- Вход в голосовой триггер создаёт комнату. Пустые комнаты, зарегистрированные ботом, удаляются; после перезапуска старые пустые комнаты очищаются.

Постоянные панели вручную создаются командами. После перезапуска бот восстанавливает представления голосований и выплат по данным SQLite; новые панели автоматически не публикуются.

## Запуск локально

PowerShell:

```powershell
$env:DISCORD_TOKEN = "ваш-токен"
python main.py
```

Linux:

```bash
export DISCORD_TOKEN='ваш-токен'
python main.py
```

Первый запуск синхронизирует slash-команды. Если задан `GUILD_ID`, синхронизация выполняется для этого сервера. Проверяйте логи хостинга при проблемах с правами, каналами или ID.
